Section 4

Development Postmortem

A readable look at what improved, what needed attention, and how the team responded.

Iteration 2 Reflection

  • Improved time estimation
  • Better testing practices with unit tests added earlier
  • Increased communication across the team
  • More collaboration across all layers

Design Pattern Used

Facade Pattern

The CreateBooking() method acts as a facade by coordinating multiple subsystems such as flightService, seatService, bookingsRepo, passengerService, and BookingValidator.

Keeps complex booking steps feeling unified

Iteration 3 Improvements

  • Technical Debt (Design): Replaced string-based seat parsing with a structured SelectedSeat object
  • Technical Debt (Bug): Fixed incorrect sorting logic for available seats

Weakness Identified

  • Poor exception handling
  • Presentation layer incorrectly throwing exceptions
  • Use of generic RuntimeException
  • Silent failures in tests

Corrective Actions

  • Moved exception logic to business layer
  • Created custom exceptions: BookingException and ValidationException
  • Enforced exception handling in method signatures

Evidence of Improvement

  • Tests now fail properly on errors
  • Can test error scenarios directly
  • Reduced cross-layer changes when fixing bugs
